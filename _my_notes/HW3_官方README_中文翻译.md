## 任务

### 环境设置

本次作业中，你需要在仿真中遥操作 SO101 机械臂。为了正确配置本作业的遥操作，请运行 `python scripts/configure_keys.py`。

该脚本会提示你为键盘上将要用于遥操作的按键进行分配。我们针对某个方向/选项该用哪个键给出了推荐，但你可以较自由地选择使用哪些键。脚本会输出一个 `keymap.json`，供整个练习使用。我们已在 MacOS 和 Ubuntu 上使用瑞士/美式键盘测试过。如果在按键分配时遇到问题，你可以修改 `configure_keys.py` 脚本，或手动编辑 `keymap.json` 文件（若这能解决问题）。这一步的重要产出是得到一个能在整个练习中使用的 `keymap.json`。

### 组件

由于我们涉及模仿学习技术栈的许多组件（大部分已为你实现），下面简要说明我们用了什么：

1. **数据存储：** 我们使用 zarr（https://zarr.readthedocs.io/en/stable/）存储数据，这是数据管理中用途广泛、被普遍采用的选择。
2. **状态：** zarr 数据集存储仿真中的原始观测。训练时通过 `--state-keys` 指定时，可以使用下面任意键（支持可选切片，例如 `"state_cube[:3]"`）：

   | 键 | 维度 | 描述 |
   |-----|-----|-------------|
   | `state_ee_xyz` | 3 | 末端执行器笛卡尔位置 (x, y, z)。 |
   | `state_ee_full` | 7 | 完整末端执行器位姿：位置 (3) + wxyz 顺序的四元数姿态 (4)。 |
   | `state_joints` | 6 → 5\* | 全部 6 个关节的关节角（Rotation、Pitch、Elbow、Wrist_Pitch、Wrist_Roll、Jaw）。\*评估时 Jaw 关节会被自动排除，剩 5 个可控关节。 |
   | `state_gripper` | 1 | 当前夹爪（Jaw）开合角。 |
   | `state_cube` | 7 | 方块自由关节状态：位置 (3) + wxyz 四元数姿态 (4)。 |
   | `state_obstacle` | 3 | 障碍物刚体位置 (x, y, z)。无障碍物时为全零向量。 |
   | `goal_pos` | 3 | 收纳箱（bin）中心位置 (x, y, z)。当箱体位置随机化时（如练习 3）有用。 |

   **仅 multicube 可用的键**（用 `--multicube` 录制时可用）：

   | 键 | 维度 | 描述 |
   |-----|-----|-------------|
   | `original_pos_cube_red` | 7 | 红色方块状态：位置 (3) + wxyz 四元数 (4)。 |
   | `original_pos_cube_green` | 7 | 绿色方块状态：位置 (3) + wxyz 四元数 (4)。 |
   | `original_pos_cube_blue` | 7 | 蓝色方块状态：位置 (3) + wxyz 四元数 (4)。 |
   | `state_goal` | 3 | 目标方块颜色 \[红, 绿, 蓝\] 的 one-hot 编码。 |

3. **动作：** 我们把动作计算为状态之间的差分，即 a_t = s_{t+1} - s_t。我们已为你实现完整末端执行器控制、仅 xyz 的末端执行器控制和关节角控制。更详细的信息见 `compute_actions.py`。


### 练习 1：MSE 策略

你的任务是训练一个策略，能够用模仿学习拾起方块、绕过一个障碍物，并把方块放进收纳箱。这分为两步：

#### 数据采集与准备

本练习的数据采集应使用 `record_teleop_demos.py` 脚本。本练习中你不必修改该脚本的任何参数。要达到约 70% 的成功率，你很可能不需要采集超过 15–20 个回（episode）的数据。具体数量因模型而异。

为了准备训练数据，你需要运行 `compute_actions.py` 脚本。该脚本要求你为策略选择一个动作空间。在作业 2 中，你已经体会过直接控制关节角与通过 IK 控制机械臂末端位置之间的区别。此外，建议尽可能简化学习问题。我们鼓励你查看 `compute_actions.py` 脚本并选择自己喜欢的动作空间。所有动作空间选择都能完成这些练习，只是遥操作的工作量不同（大致规律：动作空间越复杂，需要的遥操作越多）。

**遥操作按键**

运行遥操作脚本时，除了机械臂末端位置（使用你在 `configure_keys.py` 中分配的键）之外，还有以下控制：

| 动作 | 推荐按键 | 描述 |
|--------|----------------|-------------|
| `record` | 空格 | 开始/暂停录制。按一次开始录制一个回，再按一次暂停。 |
| `end_episode` | 回车 | 结束并保存当前录制的回，然后重置环境进入下一回。 |
| `reset` | R | 丢弃当前回（若正在录制）并重置环境。遥操作中犯错时使用。 |
| `escape` | ESC | 保存正在进行的回并退出会话。 |

屏幕叠加层会显示当前状态（`REC` / `IDLE`）、已录制回数，以及 record、end episode、reset、quit 的按键提示。按下 `escape` 时，多个已录制的回会存进同一个 `.zarr` 文件。你的遥操作流程大致应是：按下 `record` → 移动机械臂拾起方块并放入收纳箱 → 按下 `end_episode` 保存这一回并重置环境。

你还会注意到一个步数计数器，它表示数据每次被记录的进度，其上涨速度会快于你控制机械臂的速度。这套设置是在模仿真实机器人的遥操作流程。关于这个步数计数器，你唯一需要记住的是：作为遥操作者，如果你在录制过程中连续很多秒什么都不做，数据仍然会被记录。静止很多秒、把这些数据录下来再用于训练，通常会导致策略变差，因为你在某些状态下的数据分布偏向"什么都不做"。在通常的遥操作速度下，这在本设置中可以忽略。如果你担心数据质量，可以快速写一个绘图脚本检查一下。

**遥操作视角**

如果你希望视角不同，可以修改相机视角。在 `mujoco` 文件中做这个改动很容易，我们留给你自行决定。对我们来说，目前实现的相机视角已经足够。

#### 如何遥操作

你可以使用在 `configure_keys.py` 中设置的按键来移动机器人。你已经设置了一个录制键（我们建议用空格）。想录制一个回时，请务必按下它。如果你意识到自己做了错误的动作，可以用重置键（建议 R）丢弃该回并重置环境。完成一个回后，按下你设置的进入下一回的键（建议回车）。遥操作时注意：没有任何任务要求绕任意轴旋转末端执行器，你可以利用这一点。

#### 策略训练

要训练策略，你必须完成以下 TODO：

- 实现 `train.py` 中的所有 TODO。自动评分器不会 import 这个文件，因此你在这里相对自由（例如可以为了方便添加更多 CLI 参数等）。不过我们已经为你提供了一个很强的训练框架。
- 实现 `model.py` 中 `ObstaclePolicy` 的 TODO。
- 选择用于训练策略的状态空间和动作空间。运行 `train.py` 时可通过 CLI 参数设置。练习 1 训练策略时务必包含障碍物状态，这样你才能在练习 2 中复用该策略。CLI 参数支持切片，因此可以这样运行：
```bash
python scripts/train.py ... --state-keys state_ee_xyz state_gripper "state_cube[:5]" --action-keys action_ee_xyz action_gripper --policy obstacle
```

#### 策略性能测试

运行 `eval.py` 脚本，用 `--checkpoint` 指向你训练好的检查点。你可以直观查看策略的输出，也可以用 `--headless` 模式查看多次 rollout 的总成功率（比渲染快得多）。你还可以用 `--num-episodes` 增加测试的回数（最终评分使用 100 回）。

#### 交付物

当你对模型表现有信心时，可以运行：
```bash
python student_eval/run_eval --exercise 1 --checkpoint <path to your ckpt>
```
这会生成一个名为 `ex1_result.hwresult` 的文件，你可以将它提交到 Gradescope 的自动评分器。**请勿修改该文件**，因为我们会用你的模型定义和检查点验证你报告给 Gradescope 的性能，若发现篡改，我们将判为不及格。

同时，请把你的 `model.py` 和最佳检查点 `.pt` 文件提交给自动评分器。检查点文件请命名为 `ex1.pt`。请勿修改 `ObstaclePolicy` 类名，因为自动评分器会 import 它。请确保策略默认构造参数与你训练检查点时的参数一致，以便我们在评估套件中复现你的模型。

注意：这假设你使用 ARM MacOS 或 Linux 系统。如果你使用其它系统，我们建议使用 WSL、docker 或学生电脑来运行这些评估。**不要修改 `run_eval.py` 的任何内容。**

#### 注意事项与提示

- 策略的大多数问题/糟糕表现，要么是因为需要更多数据，要么是因为需要更多参数。在 ex1 和 ex2 上达到 100% 成功率所需的参数量不到 1M。
- 遥操作时不要过早手动结束回，否则末尾的动作块会被截断。
- 策略评估在自动评分器中最多运行 800 步。请确保这不会成为你策略的限制。
- 对所有策略，方块都必须被放入收纳箱（到达成功 z 阈值时，方块不能再位于夹爪内）。我们知道存在一些边缘情况，可以在表现出这种行为的同时获得高成功率。请确保你提交的策略不是这种情况，因为我们会在结果验证时额外检查。

### 练习 2：DAgger

在本练习中，你将使用课上介绍过的 DAgger。该算法允许你在策略处于分布外（out of distribution）且表现糟糕时补充数据，以提升覆盖度和成功率。我们将复用你在练习 1 中训练好的同一个策略。带着 `--adversarial` 参数重新运行 `scripts/eval.py`，你会注意到成功率低了很多。原因是障碍物分布变了，策略被迫处于分布外。你应该在评估时观察策略的执行过程，理解其失败模式。然后可以运行 `scripts/dagger_eval.py` 脚本，它允许你在分布外情形下，通过介入（step in）策略表现糟糕的时刻来补充更多专家动作。介入策略执行并提供人类专家动作的键，与之前的录制键相同。鼓励你查看 `dagger_eval.py` 文件，了解本任务其余按键映射（例如：如果某次 rollout 中你观察到失败但介入太晚，你也可以重置该 rollout，并更早介入）。之后你应在分布外情形下采集更多数据，并用练习 1 的策略重新训练。根据你的策略配置，你可能需要多次重复"观察失败模式 → DAgger → 重新计算动作 → 重新训练"这一循环，直到策略覆盖度足够大、成功率达到较高水平。如果你发现自己需要采集显著超过 25 个 DAgger 回，我们建议你重新考虑模型大小以及你遥操作这些回的方式。

#### 交付物

当你对模型表现有信心时，可以运行：
```bash
python student_eval/run_eval --exercise 2 --checkpoint <path to your ckpt>
```
这会生成一个名为 `ex2_result.hwresult` 的文件，你可以将它提交到 Gradescope 的自动评分器。**请勿修改该文件**，因为我们会在我们这边验证你报告给 Gradescope 的性能。

请把你的 `model.py` 和最佳检查点 `.pt` 文件提交给自动评分器。检查点文件请命名为 `ex2.pt`。请勿修改 `ObstaclePolicy` 类名，因为自动评分器会 import 它。

#### 提示与说明

- 与 DAgger 通常的做法一样，只有你记录的状态（和动作）才会写入 `.zarr` 文件。运行 `compute_actions.py` 时，它会从 `datasets/raw/single_cube/teleop/` 取出所有遥操作回，并从 `datasets/raw/single_cube/dagger/` 取出新的 DAgger 回，合并成一个处理后的 `.zarr` 文件。
- 屏幕上看到的 DAgger 步骤基本上与 ex1 相同。你不必担心它，但尽量不要连续很多秒静止不动。
- 取决于这个练习对你来说有多容易，你可能会（也可能不会）体会到：DAgger 在实践中可以是非常有用的工具，但同时也非常耗费资源。

### 练习 3（竞赛！）：Multicube 目标条件模仿学习

在本练习中，你要训练一个目标条件（goal-conditioned）策略，用同一个策略解决多个任务。机器人不是学习单一行为，而是接收任务信息作为输入，并据此行动。Gradescope 上有排行榜。

#### 任务描述

multicube 环境中包含三个方块：

* 红色（Red）
* 绿色（Green）
* 蓝色（Blue）

每个回开始时：

* **方块位置随机化**
* **收纳箱位置随机化**

每个回会指定一个目标方块颜色。机器人必须拾起正确的方块并放入收纳箱。策略是目标条件的，即它接收描述任务目标的额外输入。这正是模仿学习第 3 讲所讲内容的应用。

#### 数据采集

首先，照常通过遥操作录制示范数据。这次需要额外加上这个参数：

```bash
python scripts/record_teleop_demos.py --multicube
```

录制期间会额外存储以下目标信息：

* `state_goal` —— 目标方块颜色的 one-hot 编码
* `goal_pos` —— 收纳箱中心位置

#### 模型

你可以自由地在 `MultiTaskPolicy` 下实现新模型。你可以选择与之前相同的策略，也可以完全实现一个新策略。除了不允许引入额外库、不接受过大的模型之外，我们基本不设限制。


#### 训练

在 multicube 数据集上训练时，策略必须接收所有目标条件输入。

运行 `train.py` 时，状态键需包含：

- `original_pos_cube_red`
- `original_pos_cube_green`
- `original_pos_cube_blue`
- `state_goal`  
- `goal_pos`

和之前一样，你可以选择任意切片方式来进一步简化学习问题。

#### 评估

用以下命令评估训练好的策略：

```bash
python scripts/eval.py --checkpoint <path_to_checkpoint.pt> --multicube
```

#### 难度

这个 multicube 目标条件问题比之前的练习**难得多**。我们认为评估成功率接近 50% 就已经是非常强的表现。我们不期望你再次达到 90% 或类似的成功率。此外，此时你大概已经意识到，模仿学习的扩展性依赖于训练数据量。由于 ex3 一半的分数来自评价你方法的视频提交，请不要只花 10 小时遥操作来提高分数。我们鼓励你思考更聪明的方法来提升成功率（我们已经遇到了一些）。

#### 交付物

当你对模型表现有信心时，可以运行：
```bash
python student_eval/run_eval --exercise 3 --checkpoint <path to your ckpt>
```
这会生成一个名为 `ex3_result.hwresult` 的文件，你可以将它提交到 Gradescope 的自动评分器。**请勿修改该文件**，因为我们会在我们这边验证你报告给 Gradescope 的性能。

请把你的 `model.py` 和最佳检查点 `.pt` 文件提交给自动评分器。检查点文件请命名为 `ex3.pt`。请勿修改 `MultiTaskPolicy` 类名，因为自动评分器会 import 它。请确保类的默认初始化与你提交的检查点之间不存在不匹配。

**视频提交**
在 ex3 中，我们额外要求你提交一个 `.mp4` 格式的视频。视频同样不能超过 60 秒。我们希望你在视频中说明：

- 你对 ex3 的方法（我们会评价其原创性，以及在你这个设定下想法是否合理）
- 你的想法实现得如何（顺利的话为什么顺利？不顺利的话为什么不顺利？）
- 你用了多少数据，以及你的方法最终达到的成功率


## 评分

对于 ex1 和 ex2，我们根据策略性能给出 0–100 分。评分阈值如下：
  >=85% -> 100 分
  >=75% ->  80 分
  >=65% ->  60 分
  >=55% ->  40 分
  >=45% ->  20 分
  <45%  ->   0 分
对于 ex3，总共可获得 200 分。我们给策略成功率 100 分，其中 1% 成功率 = 1 分。此外，我们要求你提交 **视频提交** 一节所述的短视频。练习 3 不要求达到 100% 成功率。你不需要拿到 400/400 分才能在这份作业上拿到 6 分。
